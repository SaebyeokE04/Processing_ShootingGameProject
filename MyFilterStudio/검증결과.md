# 검증 결과

검증일: 2026-11-10 / Windows / 설치된 Processing 4.5.6 Java 모드 구성 요소 / 공식 Video 2.2.2.

## 실제 확인

- Processing Commander를 이용한 PDE 전처리 및 컴파일 성공 (`Finished.`).
- 생성된 Java를 Processing core와 공식 Video 2.2.2 JAR로 연결하여 실행.
- 합성 RGB 테스트 이미지를 이용한 자동 검증 **41개 항목 통과**.
  - 원본 필터의 픽셀 동일성, 여섯 필터의 크기 및 원본 불변성.
  - 흑백 채널 일치, 고정 필름 노이즈, 필터 강도 0의 원본 동일성.
  - 미리보기/고해상도 필름의 대응 원본 좌표 비교: 기하 좌표 차이에 따른 채널값 ±2 허용.
  - 색상 조절 결과 변경 및 반복 계산 시 비누적성.
  - 90° 회전의 크기·방향, 좌우 반전 좌표, 자르기의 크기·좌표.
  - 사진 전환 시 설정 유지, 합성 프레임 촬영 시 원본+설정 복사.
  - 동일 사진 네 필터/선택 네 사진 두 방식의 2048×2048 합성 및 여백 배경.
  - PNG/JPG 저장 후 다시 읽어 크기 확인, 한국어 경로.
  - PNG 투명도 및 JPG 흰 배경 합성.
  - 선택/저장 취소 콜백, 지원하지 않는 확장자 오류, 없는 출력 폴더로 저장 시 오류.
  - 설정 초기화 및 전체 흐름 후 원본 보존.
- 앱을 GUI로 실행하여 합성 이미지 로딩, 한글 표시, 좌/중앙/우 패널 배치, 필터 선택 버튼의 활성 표시와 미리보기 반응을 확인.
- 초기 큰 창에서 하단 메시지가 작업 표시줄에 가려질 수 있어 최종 기본 창을 1100×825로 축소. 밝기 표시를 정수로 수정.

## 직접 확인이 필요한 내용

- 실제 카메라 열기/실시간 속도/장치 변경/촬영/장치 분리/권한 거부: 실제 장치로 검증하지 않았습니다.
- 네이티브 파일 선택 대화상자를 통한 모든 취소·덮어쓰기·쓰기 권한 거부 조합은 전부 수동 검증하지 않았습니다. 콜백과 저장 엔진 오류는 자동 검사했습니다.
- GUI에서 모든 비율의 자르기 드래그와 매우 작은/큰 창 크기, Windows 배율별 클릭 위치는 수동 확인이 필요합니다. 자르기 엔진 좌표는 자동 검사했습니다.
- 대용량 사진의 최대 메모리 및 다른 PC/Video 2.1 버전 조합은 검증하지 않았습니다.

Video 라이브러리는 검증용 폴더에만 두었습니다. Processing IDE에서 실행하려면 README에 따라 스케치북에 설치해야 합니다.

## 웹캠 멈춤 보완

사용 중 웹캠 켜기에서 멈춘다는 제보에 따라 동기식 카메라 초기화를 제거했습니다. 장치 검색·생성·시작·프레임 읽기·해제를 별도 스레드로 옮겼고, UI는 연결 취소/시간 초과/실패 복귀를 담당합니다. 장치 목록 버튼도 더 이상 UI에서 Capture.list를 호출하지 않습니다. 콘솔에 오류 단계와 예외를 기록합니다.

변경 후 Processing Commander 컴파일 성공. 실제 웹캠의 재현 및 해결 여부는 미확인입니다. 네이티브 드라이버 자체의 JVM 충돌/전체 정지를 완전히 방지하는 프로세스 격리 구조는 아닙니다.

`TestCameraAsync`의 모의 지연/실패 검사 10개 통과: 검색/읽기 시간 초과, 지연 작업을 기다리지 않는 UI 복귀, 중복 연결 방지, 취소 후 늦은 프레임 무시, 오류 전달, 비동기 장치 목록, 새 프레임 갱신, 동일 프레임 재처리 방지, 비차단 종료 요청. 실제 장치는 사용하지 않았습니다. 변경된 코드로 기존 사진 처리 검사 41개도 다시 통과했습니다.
